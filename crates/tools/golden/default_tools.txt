## read_file

Read the contents of a file. Each output line is prefixed with its line number and a tab (e.g. `   1\thello`); the prefix is not part of the file, so leave it out of edit_file's old_string. Unless a limit is given, returns at most 2000 lines or 30000 characters per call, whichever comes first, and the header names the offset to continue from. There is no file size limit, and the output header reports the file's total size and line count. Lines longer than 2000 characters are cut. Image files (JPEG, PNG, GIF, WebP) are returned as inline images for visual inspection instead of raw bytes, capped by the model API's inline image size limit.

{
  "properties": {
    "limit": {
      "description": "Maximum number of lines to read (default: 2000, and a page without a limit also stops at a character budget)",
      "type": "integer"
    },
    "offset": {
      "description": "Line number to start reading from (0-based, default: 0)",
      "type": "integer"
    },
    "path": {
      "description": "Absolute or relative path to the file to read. A path starting with \"team/\" is in the shared team folder",
      "type": "string"
    }
  },
  "required": [
    "path"
  ],
  "type": "object"
}

## edit_file

Edit an existing file by replacing exact text. Each entry in 'edits' replaces old_string with new_string; old_string must match the file exactly once (include surrounding lines to make it unique) unless replace_all is true. Edits apply in order, each seeing the result of the ones before it, and the file is only written if every edit succeeds. Copy old_string from read_file output without the line-number prefix. To delete text, use an empty new_string. The file must have been read with read_file first. Use this over write_file when changing part of an existing file.

{
  "properties": {
    "edits": {
      "description": "Replacements to apply, in order. Use one entry for a single change.",
      "items": {
        "properties": {
          "new_string": {
            "description": "Text to put in its place (empty to delete)",
            "type": "string"
          },
          "old_string": {
            "description": "Exact text to replace, copied from the file",
            "type": "string"
          },
          "replace_all": {
            "description": "Replace every occurrence of old_string instead of requiring exactly one (default: false)",
            "type": "boolean"
          }
        },
        "required": [
          "old_string",
          "new_string"
        ],
        "type": "object"
      },
      "type": "array"
    },
    "path": {
      "description": "Path to the file to edit. A path starting with \"team/\" is in the shared team folder",
      "type": "string"
    }

  "required": [
    "path",

  ],
  "type": "object"

## exec

Execute a shell command and return its output. Commands run via `sh -c` with a configurable timeout (default 120 seconds). Output over 30000 bytes keeps the start of stdout and the end of stderr (and the end of stdout when the command fails) and says how many bytes were left out. Terminal colour codes are removed. Use `keys` to expose agent keys as environment variables (see agent_keys_list); use `store_output_as` to store stdout as a new agent key instead of returning it.

## workspace_restore

Restore a workspace or team file or directory to its content at a checkpoint (from workspace_history), or undo a checkpoint's own changes -- reverting each path it changed back to its content just before it, skipping any path that was changed again since so a later edit is never clobbered. Both actions checkpoint the result first, so a restore or undo can itself be undone.
